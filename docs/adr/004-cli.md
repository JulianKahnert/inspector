# CLI

This ADR defines which functions the `inspector` CLI has. The CLI sends one request per command to the app and prints the answer; the request and response types live once in `InspectorKit` and are shared with the app.

## Commands

The CLI holds no code for any single action. Every command below works for every app, and what an app can do comes from its catalog.

| Command | What it does |
|---|---|
| `inspector apps` | Lists every app found through Bonjour, each checked with `hello`, as one JSON array. An app that does not answer is listed as not live. It is the only command that is not a wire operation. |
| `inspector hello` | Names the app, the full instance name it was reached under, its process ID and the provider answering. |
| `inspector catalog` | Lists every registered action with the payload schema it accepts. |
| `inspector state [path]` | Prints the whole state, or the subtree at a dotted path. |
| `inspector send <path> [json]` | Sends one action and prints its result: whether the effects settled, the new state and the diff. A payload that does not parse as JSON is sent as a string. `${NAME}` in the payload is filled from `.inspector/.env` ([Values from `.env`](#values-from-env)). |

## Options for every command

| Option | What it does |
|---|---|
| `--app NAME` | Picks the app by its full instance name `<app> @ <device>` or by its `<app>` part. Without it, a command talks to the `instance` in `.inspector/config.json`, and without that only works while exactly one app serves. A full instance name skips the 500 ms wait for a second match ([ADR 001](001-connection.md#naming-and-finding-an-app)); `hello` and `apps` print it. |

## The `.inspector/` folder

Separate calls share no process, so what binds them to one app and device lives in a folder in the app's repository root.

**Finding it.** Every command but `apps` looks for `.inspector/` from the working directory upwards and stops at the repository root, the first directory with a `.git` entry, so a repository nested in another one, such as a worktree inside a checkout, never picks up the outer one's folder. Outside a repository the search goes up to `/`. `INSPECTOR_DIR=<path>` names the folder for one call instead, absolute or relative to the working directory.

**Which commands need it.** The folder is optional for the wire commands, so they keep working for a Mac app, a physical device and a debug build nobody set up a folder for:

| Command | Without a folder | With a folder |
|---|---|---|
| `apps` | Works; it is discovery and never looks | Ignores it |
| `hello`, `catalog`, `state` | Work as before | `instance` from `config.json` is the default for `--app`; the call is recorded in `run.json` |
| `send` | Works as before, unless the payload has a `${NAME}`: then `NO_CONFIG` | As above, plus `${NAME}` from `.env` |

`NO_CONFIG` ends a call that cannot work without the folder: a `${NAME}` placeholder with no folder to take its value from, and any command but `apps` when `INSPECTOR_DIR` names a folder that does not exist, since an explicit path that misses is a mistake to report rather than to guess around. Its `detail` is the path where the folder was expected: `INSPECTOR_DIR`, or `.inspector/` in the repository root, or in the working directory outside a repository. Commands that reach the device through Xcode need the folder's session and simulator and will end in `NO_CONFIG` without it.

**The files.**

| File | Written by | Fields |
|---|---|---|
| `config.json` | only `init`, and a session restart that rewrites `session` | `app` (the `--app` selector), `instance` (the full instance name, the default for `--app`), `bundleId`, `udid`, `session`, `workspace` (the Xcode workspace identifier), `scheme`, `logSubsystem`, `writtenAt`. Every field is optional, so a hand-written file with just `instance` works. |
| `run.json` | every command but `apps`, after it ran, failed or not | `lastStep`: `command`, `arguments` (the whole argument list) and `at`, the call's start in ISO 8601 UTC with milliseconds, so a log read from `at` on covers a failed step. Later commands add their own fields, such as the last hierarchy and screenshot paths; each command replaces only its own fields and keeps the rest. |
| `.env` | the developer, or the script that sets up the integration | `NAME=value` per line; blank lines, `#` comments, an `export ` prefix and quotes around a value are allowed, nothing inside a value is expanded |

Both JSON files are written atomically, pretty-printed with sorted keys. A failure to write `run.json` does not fail the call, whose effect already happened.

**Git.** The folder is never committed. A repository that keeps the integration permanently lists `.inspector/` in its `.gitignore`; one that adds the integration only for a debugging session lists it in `.git/info/exclude`, which leaves no trace in the repository's history.

### Values from `.env`

`send` replaces `${NAME}` (a letter or underscore, then letters, digits and underscores) in its payload with the value in `.inspector/.env`; the shell environment is never read. In a payload that is JSON already, the value goes into its strings and keys as text, so a quote in a value cannot break the JSON. Otherwise it goes into the raw argument before that is parsed, so `send counter.set '${VALUE}'` with `VALUE=42` sends the integer 42. A placeholder without a value ends the call with `ENV_MISSING` before anything is sent; the message names every missing placeholder and `detail` lists their names.

Every value filled in is masked in everything the call prints or writes: the answer on stdout, an error's `message`, `detail` and `didYouMean` on stderr, and the arguments in `run.json`. The masking replaces the value wherever it appears, also where the app's state holds it for an unrelated reason, so a short value hides more than its own use. In strings and keys the value becomes `${NAME}`; a number or boolean equal to it becomes the string `"${NAME}"`. Only filled-in values are masked: no key name such as `password` counts, and a `.env` value the payload did not use prints as it is. The masking lasts one call; a later `state` that fills nothing in prints the value.

## Output is filtered with `jq`

Every answer is shaped to be queried and filtered with `jq`, because that is how an agent or a shell script picks one value out of it:

```console
$ inspector state | jq '.counter'
$ inspector catalog | jq -r '.actions[].path'
$ inspector apps | jq -r '.[] | select(.live) | .name'
```

- Every answer goes to stdout as exactly one JSON document, never mixed with prose or progress output.
- Keys are sorted, so two answers with the same content are byte-identical and diff cleanly.
- A failure goes to stderr as one JSON error line with exit code 1, so it never ends up in the `jq` input by accident. An agent branches on `code`, never on the message.
- A usage error exits with 64.
- Discovery fails with `APP_NOT_FOUND` after about 5 s without an app, or when `--app` matches none. It fails with `AMBIGUOUS_APP` when several apps match, and the error's `detail` lists their instance names. An app that is found but stops answering ends in `TIMEOUT` ([ADR 001](001-connection.md)).
- `NO_CONFIG` and `ENV_MISSING` come from the CLI itself, before any request is sent ([The `.inspector/` folder](#the-inspector-folder)).
